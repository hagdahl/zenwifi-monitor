# Changelog

## 0.1.0 - Unreleased

### Added

- Project baseline with Git, a secret-safe configuration template, and a separate runtime log location.
- Local-first watchdog with SQLite logging, dry-run as the default, Windows Credential Manager, and explicit execute mode.

### Changed

- Machine-specific addresses, host names, and local paths were replaced with generic configuration values before publication.
- Keyring is now a fail-closed requirement for every authenticated interface.
- Documentation is synchronized with JSON configuration, the Python monitor, and the interactive run identity.
- Watchdog error tracing, effective mode, restart throttling, and dry-run regression tests were strengthened after independent review.
- The Notion payload was verified against the connected data source with the current parent structure.
- AsusRouter connections are closed through the library's verified `async_disconnect` method.
- Logic, persisted output, and project documentation were standardized to English; credential setup now retains an existing secret when its prompt is left empty.
- Added a public-use disclaimer, line-ending rules, and a Windows GitHub Actions smoke test workflow.
- Added a router configuration setup script that discovers the Windows default gateway and requires explicit `-WriteConfig` before changing local configuration.
- Router setup now verifies an HTTPS/TLS handshake, provides step-by-step usage instructions, and refuses configuration writes when TLS is unavailable.
- Added an explicitly confirmed, last-resort insecure HTTP exception for router setup; TLS remains the default.
- Added guided local data-path setup and optional Notion logging; SQLite remains the primary log.
- Documented Python 3.11 prerequisites, the governing project-instructions reference, and the complete Install.ps1 workflow; hardened Install.ps1 validation and guidance.
- Corrected authenticated router connection initialization and session cleanup before an authorized restart command.
- Documented the upstream open-source ASUSWRT router-library dependency and its role in the implementation.
- Added version-bound third-party notices and preservation rules for direct Python dependencies.
- Added the Apache-2.0 project license with David Hagdahl as copyright owner.
- Added a dry-run-first local configuration migration and a commit-bound independent pre-publication review prompt.
- Added a history-free `_public` staging workflow for public GitHub publication.
- Added a persistent local notification when Internet connectivity is confirmed after a monitor-initiated router restart.
- Added the explicit `-EnableExecution` task-registration gate and recorded the production-activation decision model.
- Added a documented plan for durable Notion delivery, local health monitoring, dependency locking, and Debian support.
- Aligned the documented data classification with what is actually delivered to Notion, and recorded the accepted risk as ADR-014. The outbox sends unmodified exception text for `Error` events, which can include the router endpoint; `README.md` and `01_docs/ARCHITECTURE.md` previously described the remote log as minimized, which the code no longer performs. Credentials remain excluded. ADR-013's rationale is corrected from exactly-once to at-least-once, and `01_docs/USER_GUIDE.md` documents the `--reset-outbox-attempts` remedy. Affected: `00_admin/DECISIONS.md`, `README.md`, `01_docs/ARCHITECTURE.md`, `01_docs/AUTHENTICATION.md`, `01_docs/USER_GUIDE.md`. Rationale: a claim the code does not support is a defect in its own right, and the risk acceptance depends on the destination being private, which a future maintainer needs told. Verified: the four suites still exit 0 and the version drift check is green; no code path changed in this entry. Rollback: revert this commit; documentation only.
- Made the health monitor notify once per transition even without a local database, and made it report an exhausted outbox as its own actionable condition. A missing database previously had no state to compare against, so every fifteen-minute firing raised another modal dialog; a last-notified stamp file beside the bootstrap log now survives the database being absent. An exhausted event is no longer counted as a waiting event, because it is never retried and would otherwise hold the state unhealthy with no action available; it is reported separately together with the remedy. Affected: `src/health.py`, `04_tests/test_health.py`. Verified under the project virtual environment on Windows: `test_health.py` exits 0 with new checks that three consecutive runs against a missing database notify exactly once, that an exhausted event is not counted as waiting, and that it is reported with the `--reset-outbox-attempts` remedy; the other three suites still exit 0. Rollback: revert this commit. The stamp file is written outside the repository and is ignored when absent.
- Bounded the outbox queue so an undeliverable event cannot occupy it for ever, and corrected the delivery guarantee. Retention now also drops undelivered events that have exhausted their retry bound and are past the retention window, retention runs on every monitoring run rather than only when remote delivery is enabled, and `--reset-outbox-attempts` lets the operator release exhausted events after fixing the remote destination. The delivery guarantee is documented as at-least-once, not exactly-once: an interrupted run can resend an event, which is preferred over dropping one. Affected: `src/watchdog.py`, `04_tests/test_outbox.py`. Verified under the project virtual environment on Windows: `test_outbox.py` exits 0 with new checks that an exhausted event can be released and delivered, that retention removes delivered and abandoned events, and that a fresh deliverable event survives retention; the other three suites still exit 0. Rollback: revert this commit. The change deletes only rows already past the retention window and adds one opt-in maintenance flag.
- Replaced the synthetic bearer-token literal in the outbox test with a neutral value. The old literal used a realistic vendor token prefix purely as test input, which would trip secret scanning on the public repository and misrepresent the project's no-secrets posture. Affected: `04_tests/test_outbox.py`. Verified: `test_outbox.py` still exits 0 and still asserts that the token value is absent from the persisted error detail and that the redaction marker is present. Rollback: revert this commit; it changes test input only, no production code path.
- Queued Notion delivery in a durable local outbox. Events are committed to SQLite before any remote call and marked delivered only after a successful Notion response; undelivered events are sent oldest first, delivery stops on the first failure, retries are bounded per event and per run, delivered events are purged after a retention window, and persisted error detail is sanitized so no authorization header is stored. Bootstrap logging is now size-bounded and rotated before write. Affected: `src/watchdog.py`, `src/_logrotate.py`, `04_tests/test_outbox.py`, `config.example.json`. Rationale: an outage is exactly when a remote call cannot succeed, so remote logging must be queued rather than attempted inline. Verified under the project virtual environment on Windows: `test_outbox.py` exits 0, covering undelivered storage, stop-on-first-failure, oldest-first exactly-once delivery, token sanitization, the retry bound, retention and log rotation with the newest line preserved; `test_watchdog.py` still exits 0. Rollback: revert this commit. The added `events` columns are additive and older rows keep their defaults; no scheduled task or router configuration was changed.
- Added a local health monitor on its own silent scheduled job. `src/health.py` is standard-library only by design, so it keeps working when the project virtual environment does not. It reports a stale run, an unreadable database, a changed bootstrap log and a stalled outbox, notifies only on a new or escalating unhealthy state, clears once healthy runs resume, and can never restart the router. `Install.ps1 -RegisterHealthTask` registers it on a fifteen-minute task through the same silent wrapper and asserts that it is interactive, runs via `wscript.exe`, and never carries `--execute`. Recorded as ADR-013. Affected: `src/health.py`, `04_tests/test_health.py`, `scripts/Install.ps1`, `.github/workflows/test.yml`, `00_admin/DECISIONS.md`, `01_docs/ARCHITECTURE.md`, `00_admin/HANDOVER.md`, `00_admin/GLOSSARY.md`, `01_docs/USER_GUIDE.md`. Rationale: silent monitoring needs an independent observer that does not share the watchdog's dependencies. Verified under the project virtual environment on Windows: `test_health.py` exits 0, covering stale-run and stalled-outbox detection, escalation notifying exactly once and a steady unhealthy state not renotifying, plus static assertions that the module imports no third-party dependency and contains no restart path. No scheduled task was created; registration is left to the project owner. Rollback: revert this commit. The `health` table is additive and no scheduled task was changed.
- Generalized `scripts/RouterWatchdog.vbs` into the single silent launcher for every scheduled job: it accepts `--script=<path relative to the project root>`, still forwards `--execute`, and keeps window mode 0 with no wait. `Install.ps1 -RegisterTask` now fails unless the registered task action is `wscript.exe`, and reboot and recovery notices are spawned through `pythonw.exe` with `CREATE_NO_WINDOW` so no console flashes. Affected: `scripts/RouterWatchdog.vbs`, `scripts/Install.ps1`, `src/watchdog.py`, `00_admin/DECISIONS.md` (ADR-012), `01_docs/ARCHITECTURE.md`, `00_admin/HANDOVER.md`, `01_docs/USER_GUIDE.md`, `AGENTS.md`. Rationale: an unattended job must raise no UI surface and steal no focus, and a second scheduled job is planned for health monitoring. Verified in the real spawn context on the Windows host: launching the wrapper with no arguments added exactly one `runs` row with effective mode `dry-run` and left zero visible windows; launching it with `--script=` and `--execute` against a temporary probe script showed the wrapped script received `--config <path> --execute`, and the probe was removed afterwards. Rollback: restore the previous single-purpose wrapper and the previous `launch_*_notice` bodies; the registered task needs no change because its action and arguments are unchanged.
- Added project-wide file version marking: a root `VERSION` file as the single source of truth, a version marker in every tracked file, `config_version` in the configuration schema, `scripts/check_versions.py` as a standard-library drift check with `--json` output and exit codes 0/1/2, and a CI gate that fails the build on drift. Affected: `VERSION`, `scripts/check_versions.py`, `04_tests/test_check_versions.py`, `.github/workflows/test.yml`, `scripts/Migrate-LocalConfig.ps1`, `config.example.json` and a one-line marker in every other tracked file. Rationale: the governing standard prescribes no versioning scheme for downstream projects, so the scheme is chosen here and recorded as ADR-011. Verified by running `python scripts/check_versions.py` (ALL GREEN, 30 tracked files checked) and `python 04_tests/test_check_versions.py` against a temporary Git repository covering the green, stale, missing-marker and changelog-drift branches.
- Hardened Windows PowerShell compatibility, configuration validation, task registration, TLS setup messaging, CI permissions, and bootstrap-failure documentation after independent review.

### Rollback

- Remove the version marking by reverting the commit that introduced it. The marker lines are comments in every file type except `config.example.json`, where `config_version` is an additive key that `validate_config` ignores, so reverting cannot change monitoring behaviour. Deleting `VERSION` alone makes `check_versions.py` exit 2.
- Restore the project baseline by removing the local Git commit that introduced the change. No scheduled task, router configuration, or external account was changed in this step.
